# DramaCoo 1.1 优化 PRD

> 对象项目：DramaCoo（本地 AI 短片创作 Agent，Python FastAPI + Next.js）
> 参考项目：火宝 Huobao Drama（仅作功能对标，遵守 CC BY-NC-SA 合规边界，只借鉴设计、用 Python 重新实现，不复制其代码与提示词文案）
> 版本：1.1（优化稿）｜状态：草案｜适用对象：产品 / 研发 / 测试

---

## 0. 背景与优化目标

DramaCoo 现有能力（一句话创意 → 6 阶段 → 成片）已跑通，但存在两个明显短板：

1. **能力缺口**：无道具资产、无 @提及参考图映射、无统一生成任务与失败重试、无缩略图/海报帧。
2. **无沉淀**：生成的项目没有像样的存放区域；好的素材（角色图/场景图/视频片段）无法沉淀为可复用资产。

本次优化两大方向：

- **方向 A｜补齐能力**：道具资产、@提及参考图映射、统一生成任务+失败重试、缩略图与海报帧。
- **方向 B｜项目管理与资产管理**：项目有存放、查找、归档的区域；素材可沉淀、可手动上传、可复用。

---

## 1. 目标用户与核心任务

- **目标用户**（沿用）：短视频/短剧创作者、自媒体/MCN、AI 工具爱好者。
- **新增核心任务**：
  1. 创作完成后能**管理项目**（看到封面、状态，可搜索、归档、删除）。
  2. 生成过程中的**好素材能沉淀**为可复用资产（角色图、场景图、道具图、视频片段、成片），并可手动上传外部素材进库。

---

## 2. 输入、过程和产物

- **输入**（新增）：除「一句话创意」外，用户可**手动上传素材**（角色图、参考图等）进入素材库。
- **过程**（沿用 + 新增）：
  - 6 阶段停点确认（沿用）。
  - 项目库 / 素材库的浏览、搜索、归档、复用（新增）。
- **产物**（新增）：
  - 成片（沿用）。
  - 项目记录：封面/缩略图、标题、风格、状态、创建时间。
  - 素材资产：角色图、场景图、道具图、视频片段、成片，带缩略图/海报帧。

---

## 3. Agent 主链路

- 主流程沿用 6 阶段停点确认，每阶段产物需用户确认后才进入下一阶段。
- 新增能力对链路的改动：
  - **道具生成（新增环节）**：第 2 阶段由「角色/场景设计」升级为「资产设计（角色/场景/道具）」。道具完整经历「三问判定提取 → 生成白底单品图（可多版本）→ 可修改/重新生成/上传替换 → 停点确认」四个环节，与角色、场景同批展示确认。
  - **@提及映射**：在分镜/视频提示词层生效，提示词中 `@角色名 / @场景名 / @道具名` 自动替换为对应参考图标记。
  - **任务重试**：图片/视频生成统一走任务生命周期，失败任务可一键重试，不影响已完成的镜头。

---

## 4. 什么算"生成得好"

- 沿用：6 阶段产物完整、可确认、可修改后重新生成。
- 新增 4 项补齐能力的验收标准：**待样例打分**（首次真实冒烟时用 5-10 条真实样例打分定标准）。
- 瑕疵容忍：个别格式/标点瑕疵可接受，由产品经理判断。

---

## 5. 交付阶段与优先级

分三批交付（按推荐 C 分期）：

| 批次 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| **第一批** | ① 统一生成任务 + 失败重试　② 缩略图 + 海报帧 | 纯后端工具，风险低，立即见效 |
| **第二批** | ③ 项目库　④ 素材库（项目内沉淀 + 手动上传）　⑤ SQLite 数据层 | 数据层升级，支撑项目/资产管理 |
| **第三批** | ⑥ 道具资产　⑦ @提及参考图映射 | 需改动 prompt 与 agent，放在数据层稳定后 |

- 二期（本次不做，仅预留设计）：全局跨项目素材库、素材收藏复用、素材去重。

## 6. 模型与成本约束

- 沿用：通义 DashScope + 火山方舟（ARK），LLM `qwen3.7-max`、VLM `qwen3.5-plus`、图像 `wan2.7-image`、视频 `wan2.7-i2v / wan2.7-r2v`。
- 成本由用户自有 API Key 承担，本项目不新增成本。

## 7. 数据与非功能要求

- **数据存储升级为 SQLite**（替代/增强现有 JSON 会话文件），建项目表、素材表、任务表，支撑搜索、去重、复用。
- **缩略图规格**：图片 400px webp 缩略图；视频抽海报帧（封面用）。
- **本地部署**：数据不出本机（沿用）。
- **合规边界**：只借鉴火宝功能设计，用 Python 重新实现，不复制火宝代码与提示词文案。

## 8. 上线与账号

- 本地单用户，无登录（沿用现状）。
- 无云端认证、无云费用（本地部署）。

## 附录：新增功能需求详述

### A. 补齐能力

**A1. 道具资产（Props）**
- 第 2 阶段升级为「资产设计」，在角色、场景之外新增道具类型，三者并列。
- 道具判定采用"三问"法（借鉴火宝思路，自行重写）：
  1. 删掉它剧情是否依然成立？（成立则不提取）
  2. 它只是随手使用的日常物品（手机/筷子/杯子/烟）吗？（是则不提取）
  3. 它是场景陈设（桌椅/灯具/门窗/装饰）吗？（是则不提取）
- 道具字段：`name / type / description（只写物理外观）/ 白底单品图`。
- 一集通常 0-3 个道具，超过按剧情重要性取前 3，没有就一个都不提取。
- 道具可在分镜/视频提示词中 @引用。

**道具生成环节（在第 2 阶段「资产设计」内）**：
1. **道具提取**：Agent 按"三问"法从剧本提取道具清单。
2. **道具图生成**：为每个道具生成"白底单品图"（纯白背景静物，固定外观，供后续特写/反复出现时复用）。
3. **可干预**：道具图支持多版本、重新生成、手动上传替换（与角色图、场景图同机制）。
4. **停点确认**：道具图与角色图、场景图一同在停点 3 展示，用户确认后进入分镜阶段。

**A2. @提及参考图映射**
- 分镜/视频提示词中用 `@角色名 / @场景名 / @道具名` 引用参考素材。
- 生成时自动替换为对应参考图标记（如 `@小明 → @图片1小明`）。
- 名字必须与资产列表精确匹配。

**A3. 统一生成任务 + 失败重试**
- 图片/视频生成统一走任务生命周期：创建(processing) → 调用 → 同步完成或异步轮询 → 下载落盘 → 回写业务数据。
- 失败任务记录错误信息，可一键「重试失败」。
- 任务进度可追踪（进度条/状态）。

**A4. 缩略图 + 海报帧**
- 图片生成后自动产出 400px webp 缩略图（列表页用）。
- 视频生成后自动抽海报帧（封面用）。
- 列表/预览优先加载缩略图与海报帧，点开大图/播放才加载原文件。

### B. 项目管理与资产管理

**B1. 项目库**
- 升级现有「历史会话列表」为「项目库」：每个项目有封面、标题、风格、状态、创建时间。
- 支持搜索、归档、删除。
- 平级结构（一个会话 = 一个项目 = 一部多集短剧），不做"项目→剧集"两层。

**B2. 素材库**
- 项目内素材沉淀：自动归档本项目生成的角色图、场景图、道具图、视频片段、成片。
- 支持手动上传素材（现成角色图/参考图等）进库。
- 二期（预留）：全局跨项目素材库、素材收藏复用、去重。

### C. 数据存储

**C1. SQLite 升级**
- 新增项目表、素材表、任务表（兼容现有会话 JSON，历史会话可迁移或双读）。
- 支撑项目搜索、素材去重、跨项目复用。
