## 一、阶段目标

### 交付范围（对齐 PRD 第三批）
1. **道具资产（Props）**：第 2 阶段「角色/场景设计」升级为「资产设计（角色/场景/道具）」，新增道具类型。
2. **@提及参考图映射**：分镜/视频提示词中可用 `@角色名 / @场景名 / @道具名` 引用素材，生成时自动替换为对应参考图。

### 阶段产物
- 道具提取（"三问"法）+ 白底单品图生成 + 可干预（多版本/重新生成/上传/从素材库选）
- 道具在停点 3 与角色图、场景图一同展示确认
- `@提及` 解析与替换逻辑，接入分镜/视频提示词
- 相关 prompt 模板 + mock 测试

### 验收标准
- 第 2 阶段能提取道具清单（一集 0-3 个，按"三问"法判定）。
- 每个道具有白底单品图，支持多版本、重新生成、上传替换、从素材库选。
- 道具图与角色/场景图一起在停点 3 确认，确认后进入分镜。
- 分镜/视频提示词里的 `@角色名/@场景名/@道具名` 能正确替换为对应参考素材。
- 道具可被收藏进全局素材库（复用第二批能力）。

### 明确不做
- 全局跨项目素材库、素材去重（二期）
- 角色级 Agent 互评、跨镜头连贯性审查（路线图，不在本次）
- 多语言界面（不在本次优化范围）

### 本阶段打通的主链路片段
剧本 → 资产设计阶段提取「角色+场景+道具」→ 道具生成白底单品图 → 停点 3 一并确认 → 分镜提示词中 @提及 道具/角色/场景 → 视频生成时替换为参考素材。

## 二、技术适配摘要

- 引用《技术适配声明》结论：产品形态「分阶段确认的多媒体创作 Agent」，开发路径**纵向切片**。
- 本阶段沿用现有技术栈：Python 3.12 + FastAPI + SQLAlchemy + Pillow，**不引入新框架**。
- 本阶段偏离/暂缓：
  - 道具图**不做独立 VLM 评估选优**（复用角色/场景已有的多版本 + 手动选择机制，降低复杂度；白底单品图本身较简单）。
  - @提及**先做"后端解析替换"，前端 @ 选择输入框作为可选项**（先用文本直接输入 @名字）。

## 六、数据、资产与状态

### 6.1 道具 artifact 结构（第 2 阶段 character_design）

在现有 `characters` / `settings` 之外，新增 `props` 列表：

```json
{
  "props": [
    {
      "id": "prop_xxxx",
      "name": "旧怀表",
      "type": "信物",
      "description": "黄铜外壳、表面有划痕、表链断裂",
      "selected": "code/result/image/<sid>/Assets/props/prop_xxxx.png",
      "versions": [".../prop_xxxx.png"],
      "status": "done"
    }
  ]
}
```

- 道具目录：`code/result/image/<sid>/Assets/props/`（复用现有上传/缩略图机制）。
- 道具图 = 白底单品图，缩略图沿用 `_thumb.webp`。

### 6.2 @提及规则

- 格式：`@名字`（名字 = 资产列表中的 `name`，精确匹配）。
- 替换目标：
  - 视频生成（first_frame / start_end_frame / reference 模式）：`@角色名` → 对应角色图参考路径，`@场景名` → 场景图，`@道具名` → 道具图。
  - 分镜描述中的 @提及：保留在提示词中，供用户编辑；生成视频时才解析替换。
- 未匹配的 @名字：保留原样，不报错（避免生成中断）。

### 6.3 状态机

- 道具沿用资产的 `pending / running / done / failed` 状态 + `selected` / `versions`。
- 停点 3（资产设计）确认条件扩展为：角色、场景、道具的选中项都就绪（道具可为空）。

## 七、API / 工具设计

- 道具的生成/干预**复用现有 `execute_stage` / `intervene` 接口**，扩展 intervention 字段：
  - `regenerate_props`: [prop_id] —— 重新生成道具

- 上传/从素材库选：复用现有 `upload_image` / `attach_library_asset`（item_type 增加 `props`）。
- @提及**不新增 API**（内部解析逻辑）。

## 八、Prompt 设计

### 8.1 道具提取（`prompts/prop/extract_props_zh.txt`）

- 角色：制片助理。
- 输入：当前集剧本。
- 判定"三问"（借鉴火宝思路、自行重写）：
  1. 删掉它剧情是否依然成立？（成立则不提取）
  2. 它只是随手使用的日常物品（手机/筷子/杯子/烟）吗？（是则不提取）
  3. 它是场景陈设（桌椅/灯具/门窗/装饰）吗？（是则不提取）
- 输出：道具清单 JSON（name / type / description），一集 0-3 个，按剧情重要性排序。
- 结构化输出 + Pydantic 校验 + 宽容解析（数量超标记为瑕疵，不反复重试）。

### 8.2 白底单品图（`prompts/prop/prop_zh.txt`）

- 白底单品静物图，纯白背景，居中，只写物品物理外观（材质/颜色/形状/大小/新旧），不含剧情用途。

### 8.3 @提及（无需 prompt，纯代码）

- 在 storyboard_agent 生成分镜描述时，允许 @名字；video_agent 解析替换。

## 十、测试要求

### 第一层：mock 自动化测试（pytest，离线）

1. 道具提取解析：三问判定正确、清单 0-3 个、JSON 结构校验。
2. 白底单品图 prompt：模板可加载、参数填充正确。
3. @提及解析：`@角色名/@场景名/@道具名` 正确替换为对应路径；未匹配保留原样；多个 @提及、重名、边界情况。
4. 道具 artifact：生成/选择/上传/从素材库选后状态与 versions 正确。
5. 停点 3 确认：道具为空时不影响角色/场景确认；道具未选时状态为 waiting。
6. 回归：角色/场景生成不受道具新增影响。

### 第二层：真实模型冒烟（验收前，真实 Key）

- 生成 1 个道具白底单品图（约 0.2 元），验证任务记录 + 缩略图 + 停点展示。
- 一条含 @提及 的视频提示词，验证替换后的参考素材正确注入。
- 记录模型、耗时、成本。

## 十一、验收清单（产品经理照着点）

- [ ] 1. 新建项目走到「角色设计」阶段，能看到「角色 / 场景 / 道具」三组（道具组可为空）。
- [ ] 2. 剧本里有明显道具时，道具组能自动提取出 0-3 个道具（名字/类型/描述）。
- [ ] 3. 点道具的「生成」，生成白底单品图，支持重新生成、上传、从素材库选。
- [ ] 4. 道具图能点「素材」收藏进全局素材库。
- [ ] 5. 停点 3 确认后，进入分镜/视频阶段。
- [ ] 6. 在分镜/视频提示词里输入 `@角色名`，生成视频时能正确引用对应角色图（生成的视频角色一致性更好）。
- [ ] 7. 服务重启后，道具数据不丢。
