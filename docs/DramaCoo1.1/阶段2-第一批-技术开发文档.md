> 本文档只覆盖第 2 阶段（第一批）。SQLite / 项目库 / 素材库属第二批，道具 / @提及属第三批，**本阶段不实现**。

## 一、阶段目标

### 交付范围（对齐 PRD 第一批）
1. **统一生成任务 + 失败重试**：图片/视频生成统一走「创建 → 处理中 → 完成/失败」任务生命周期；失败任务记录错误信息，可一键重试；任务进度可追踪。
2. **缩略图 + 海报帧**：图片生成后自动产 400px webp 缩略图；视频生成后自动抽海报帧；列表/预览优先加载缩略图与海报帧。
3. **ffmpeg 内置**：用 `imageio-ffmpeg` 内置 ffmpeg 二进制，替代系统依赖（支撑海报帧 + 后续拼接），免用户安装。

### 阶段产物
- `core/tasks.py`：生成任务记录 Store（JSON 结构化文件，schema version 1，原子写入）
- `core/thumbnail.py`：缩略图（Pillow）+ 海报帧（ffmpeg）生成模块
- `utils/ffmpeg_bin.py`：ffmpeg 二进制解析器（env 覆盖 → 系统 → 内置）
- retry 相关 API + 现有前端最小重试入口
- pytest mock 测试

### 验收标准（对齐 PRD，可细化）
- 每次图片/视频生成都有对应任务记录，状态/错误信息可查。
- 生成失败后，前端可对失败项一键重试，重试只跑失败项、不影响已成功项。
- 生成的图片有 `_thumb.webp` 缩略图、视频有 `_poster.jpg` 海报帧，列表页加载缩略图/海报帧。
- 进程重启后，进行中的任务可被识别（标记为失败可重试），不残留"永久处理中"。
- ffmpeg 不再依赖系统安装（本机未装 ffmpeg 也能完成海报帧与拼接）。

### 明确不做（防范围蔓延）
- SQLite 数据库、项目库、素材库、手动上传（第二批）
- 道具资产、@提及映射（第三批）
- 全局跨项目素材库、收藏、去重（二期）
- 前端大改版（本阶段只加最小重试/缩略图展示）

### 本阶段打通的主链路片段
生成图片/视频 → 写入任务记录（处理中）→ 成功则落盘 + 生成缩略图/海报帧 + 任务置完成；失败则记录错误 + 任务置失败 → 用户重试 → 重新走该任务生命周期。

## 六、数据、资产与状态

### 6.1 任务记录（JSON 结构化文件）

- 位置：`code/data/tasks/<session_id>.json`（按会话一个文件，与现有 session 同目录模式）。
- schema 版本：`1`，写入时携带 `schema_version`，读取时校验。
- 原子写入：临时文件 + `os.replace`（复用现有 session 持久化做法）。
- 损坏处理：读取失败时备份为 `.corrupt` 并跳过，不阻断启动。

**任务字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| task_id | string | 唯一 ID（uuid） |
| type | string | `image` / `video` |
| session_id | string | 所属会话 |
| stage | string | 所属阶段（character_design/reference_generation/video_generation） |
| item_type | string | characters/settings/scenes/clips |
| item_id | string | 资产条目 ID（如 `char_xx`、`seg_01_01`） |
| provider / model | string | 本次使用的厂商与模型 |
| prompt | string | 生成提示词 |
| params | object | 生成参数（尺寸/时长/参考图等） |
| status | string | `processing` / `completed` / `failed` |
| error | string/null | 失败原因（只记 message，不记堆栈） |
| result_paths | array | 产物本地路径 |
| attempt | int | 第几次尝试 |
| created_at / updated_at / completed_at | number | 时间戳 |

### 6.2 状态机

```text
processing ──成功──▶ completed
processing ──失败──▶ failed（记录 error）
failed ──重试──▶ processing（attempt +1）
```

- 进程重启后，磁盘上仍为 `processing` 的任务（进程崩溃遗留）在加载时统一置为 `failed`（error="进程中断，请重试"），保证不残留"永久处理中"。

### 6.3 资产文件

- 图片缩略图：`<原名>_thumb.webp`（长边 400px，quality 80）。
- 视频海报帧：`<原名>_poster.jpg`（ffmpeg 抽首帧）。
- 缩略图/海报帧与原文件同目录，前端列表用缩略图、点开大图/播放才用原文件。

## 七、API / 工具设计

### 新增接口（沿用现有 `/api` 前缀）

**GET `/api/project/{session_id}/tasks`**
- 请求：无（可选 `?status=failed` 过滤）。
- 响应：`{"tasks": [{task 字段...}]}`。
- 错误：`404` 会话不存在。

**POST `/api/project/{session_id}/tasks/{task_id}/retry`**
- 请求体：无。
- 响应：`{"status": "retrying", "task_id": "..."}`。
- 规则：仅 `failed` 状态可重试；重试后置 `processing` 并异步重新执行该任务。
- 错误：`404` 任务不存在 / `409` 状态非 failed。

**POST `/api/project/{session_id}/tasks/retry_failed`**（批量）
- 请求体：`{"stage": "video_generation"}`（可选，指定阶段）。
- 响应：`{"retried": 3, "tasks": ["..."]}`。
- 规则：重试该会话内所有 `failed` 任务（可限定阶段）。

- 错误统一格式：`{"error": {"code": "...", "message": "..."}}`，不回显堆栈。
- 重试执行复用现有 SSE（`execute_stage` 的 `asset_complete` 进度事件），前端不新增流式协议。

## 十、测试要求

### 第一层：mock 自动化测试（pytest，离线可跑，模型调用全 mock）

1. 任务创建：字段齐全、schema_version=1、落盘可读。
2. 成功路径：任务 `processing → completed`，result_paths 写入。
3. 失败路径：任务 `processing → failed`，error 为 message（不含堆栈）。
4. 重试路径：`failed → processing`，attempt 递增；非 failed 状态重试返回 409。
5. 重启恢复：磁盘上残留 `processing` 任务加载后置为 `failed`。
6. 损坏文件：`tasks` JSON 损坏时不阻断启动、生成 `.corrupt` 备份。
7. 缩略图：给定图片产 `_thumb.webp`，尺寸 ≤ 400px；视频产 `_poster.jpg`。
8. ffmpeg 解析器：env 覆盖 → 系统 → 内置的优先级正确；都缺失时报可操作错误。
9. 原子写入：写入中断不产生半截文件。

### 第二层：真实模型端到端冒烟（验收前，真实 Key）

- 用真实 Key 跑：生成 1 张角色图 → 断言任务 completed + 缩略图存在；生成 1 段视频 → 断言任务 completed + 海报帧存在。
- 人为触发一次失败（如错误模型名）→ 断言任务 failed + error 可读 → 调 retry 成功。
- 用 `curl -N` 验证 SSE 事件仍以 `done`/`error` 正确收尾。
- 记录：模型、耗时、成本、结果；格式合规率"首测即合规/重试后合规"分开记（对应台账 D2 待样例打分）。
