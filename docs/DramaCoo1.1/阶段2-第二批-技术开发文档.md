> 本文档只覆盖第二批。道具 / @提及属第三批，本阶段不实现；全局跨项目素材库属二期，仅预留表结构。

## 一、阶段目标

### 交付范围（对齐 PRD 第二批）
1. **SQLite 数据层**：新增项目表、素材表、任务表；历史会话 JSON 与产物文件一次性迁移，兼容双读。
2. **项目库**：把现有「历史会话列表」升级为项目库——每个项目有封面、标题、风格、状态、创建时间；支持搜索、归档、删除。
3. **素材库**：项目内素材自动沉淀（角色图/场景图/参考图/视频片段/成片）+ 支持手动上传素材。

### 阶段产物
- `core/db.py`：SQLAlchemy engine + session（SQLite，WAL 模式）
- `core/models.py`：projects / assets / tasks 三张 ORM 表
- `core/asset_store.py`：素材沉淀扫描 + 手动上传写入
- 迁移脚本：JSON → SQLite（幂等，带 schema_version 标记）
- 项目库 / 素材库 API + 前端最小界面

### 验收标准
- 历史项目能在项目库里看到封面、标题、状态、时间，可搜索、归档、删除。
- 每个项目的素材（角色图/场景图/参考图/视频/成片）自动出现在素材库，可手动上传新增素材。
- 服务重启后项目库/素材库数据不丢（SQLite 持久化）。
- 生成任务从 JSON 迁到 SQLite 后，任务查询/重试不受影响。

### 明确不做（防范围蔓延）
- 道具资产、@提及（第三批）
- 全局跨项目素材库、素材收藏、去重（二期，仅预留字段）
- 多用户账号、云端同步（不在范围）
- 项目→剧集两层结构（沿用"一个会话=一个项目"平级）

### 本阶段打通的主链路片段
生成完成 → 素材自动沉淀入 SQLite → 项目库显示项目（含封面/状态）→ 素材库显示该项目全部素材 → 用户可手动上传素材 → 可搜索/归档/删除。

## 二、技术适配摘要

- 引用《技术适配声明》结论：产品形态「分阶段确认的多媒体创作 Agent」，开发路径**纵向切片**（本阶段数据层 + 前端界面一起做）。
- 本阶段启用按需模块：**SQLite + SQLAlchemy**（由「项目管理/资产管理需要多实体关系、筛选、去重、复用」触发，对应 PRD Q3、台账 D10）。
- 本阶段偏离/暂缓：
  - **Alembic 暂缓**：本地 MVP 阶段用「schema_version 字段 + 幂等 CREATE TABLE IF NOT EXISTS」管理建表，不做 Alembic 迁移链；未来引入 Alembic 时从 schema_version 起步。
  - **会话 JSON 保留**：orchestrator 运行态（artifacts/status/stage_progress）继续存 JSON，SQLite 只承载「项目/素材/任务」的查询与管理元数据（双读），避免重构状态机。

### 6.2 迁移与双读策略

- 启动时 `init_db()`：幂等建表 + 执行 `migrate_to_sqlite`（若 `schema_version` 低于当前版本）。
- 迁移内容：
  1. 遍历 `code/data/sessions/*.json` → 写入 projects 表（title/idea/style/status/cover）。
  2. 扫描 `code/result/image|video/{sid}/` → 写入 assets 表（自动识别角色图/场景图/参考图/视频片段/成片 + 缩略图/海报帧）。
  3. 遍历 `code/data/tasks/*.json` → 写入 generation_tasks 表。
- **双读**：orchestrator 运行态继续用会话 JSON；项目库/素材库/任务查询走 SQLite。迁移幂等（按 id 存在则跳过/更新）。

### 6.3 资产文件

- 沿用现有 `code/result/` 目录，素材表只做索引，不移动文件。
- 缩略图/海报帧沿用第一批产物（`_thumb.webp` / `_poster.jpg`）。
- 手动上传的素材存 `code/result/upload/{sid}/`，同样写 assets 表。

## 七、API / 工具设计

### 项目库（沿用 `/api` 前缀，改造 sessions 路由）

**GET `/api/sessions`**（升级）
- 请求：`?search=关键词&archived=false`
- 响应：`{"projects": [{id, title, style, status, current_stage, cover_image, episode_count, archived, created_at}]}`
- 规则：从 SQLite projects 表查询；`search` 按 title/idea 模糊匹配。

**PATCH `/api/sessions/{id}/archive`**
- 请求：`{"archived": true/false}`
- 响应：`{"status": "ok", "archived": ...}`

**DELETE `/api/sessions/{id}`**（沿用，删除项目时级联清理 assets + 结果文件 + 会话 JSON）

### 素材库（新增 assets 路由）

**GET `/api/project/{session_id}/assets`**
- 请求：`?asset_type=character|scene|...&media_type=image|video`
- 响应：`{"assets": [{id, asset_type, name, media_type, file_path, thumb_path, source, created_at}]}`

**POST `/api/project/{session_id}/assets/upload`**（手动上传）
- 请求：multipart，`file`（图片 jpg/png/webp，或视频 mp4；图片 ≤25MB，视频 ≤500MB）
- 响应：`{"status": "ok", "asset": {...}}`
- 规则：格式/大小双重校验，安全文件名，写入 `code/result/upload/{sid}/` + assets 表，图片自动产缩略图。

**DELETE `/api/project/{session_id}/assets/{asset_id}`**
- 规则：删除素材记录 + 清理关联文件（软删除/物理删除视确认）。

- 错误统一：`{"error": {"code", "message"}}`，不回显堆栈。

## 十、测试要求

### 第一层：mock 自动化测试（pytest，离线）

1. 建表幂等：`init_db()` 多次调用不报错，表结构正确。
2. 迁移：给定临时 session JSON + 产物文件 → 迁移后 projects/assets/generation_tasks 行数正确。
3. 迁移幂等：重复迁移不产生重复行。
4. 项目列表：搜索/归档过滤正确。
5. 素材沉淀：扫描角色图/场景图/参考图/视频片段/成片 → 类型、media_type、缩略图路径正确。
6. 手动上传：合法文件写入 assets + 文件落盘 + 缩略图生成；非法格式/超大小拒绝。
7. 删除：删除素材清理文件；删除项目级联清理 assets。
8. 任务表：迁移后任务查询与重试（复用第一批逻辑）不受影响。

## 十二、风险与待确认项

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| JSON→SQLite 迁移 | 历史会话/产物多，迁移可能漏或重复 | 幂等迁移 + 单测覆盖 + 迁移后校验行数 |
| 双读一致性 | 会话 JSON 与 SQLite 可能不一致 | 以 JSON 为运行态权威，SQLite 定期/变更时同步 |
| SQLAlchemy 新依赖 | 需安装 | 加入 requirements/pyproject，安装验证 |
| 素材扫描性能 | 项目多、文件多时扫描慢 | 增量扫描（按 mtime/已索引判断） |

**必须由产品经理决定的问题：无**（沿用台账 D6/D10 已定结论）。
