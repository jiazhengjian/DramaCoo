# 工作室前端

本目录是 Next.js 前端。以下命令均在 `frontend` 目录执行。

## 启动

首次使用先安装依赖，再启动开发服务。

```bash
npm ci
npm run dev
```

浏览器打开 [http://localhost:3002](http://localhost:3002)。默认生产启动命令也是使用 3002 端口。

```bash
npm run build
npm run start
```

前端默认将 API 和媒体请求转发至 `http://127.0.0.1:8000`。需要读取已有项目、素材和配置时，请先启动项目后端。后端地址变化时，可通过 `BACKEND_API_URL` 指定地址。

```bash
BACKEND_API_URL=http://127.0.0.1:8000 npm run dev
```

## 独立预览

已有前端服务运行时，可另开一个终端，用单独的缓存目录和端口预览修改。

```bash
NEXT_DIST_DIR=.next-preview npx next dev -p 3004
```

浏览器打开 [http://localhost:3004](http://localhost:3004)。此预览与默认 `.next` 构建目录分开；停止时在对应终端按 `Ctrl+C`。

## 代码检查

```bash

```

构建检查使用独立的 `.next-check` 目录。若要运行这份构建，可执行以下命令，再打开 [http://localhost:3004](http://localhost:3004)。该端口已有预览服务时，先停止预览服务。

## 浏览器验收

先启动后端和前端，再在浏览器执行以下步骤。

1. 打开首页，查看左侧导航。应显示「工作室」，不再显示「文艺短视频」「数字人口播」。点击其他保留入口，应能进入对应页面。
2. 打开「工作室」并滚动至页面底部。应没有独立的「历史记录」模块；打开「项目库」，确认仍可找到已有项目。
3. 依次进入「临时工作台」「动作迁移」「设置」「项目库」「素材库」。大标题和描述应在内容区左上角，前三页不再有固定的顶部品牌栏。
4. 在项目库输入搜索词、切换归档筛选；在临时工作台切换工具；在动作迁移展开参数设置。检查操作控件、选中态和弹出内容是否清晰可见。
5. 对照即梦参考页检查页面背景、侧边栏、卡片边界、标题层级、按钮和表单样式。检查页面底部以及有滚动区域的面板，避免遗漏局部样式。
6. 在浏览器开发者工具中切换到约 390 px 手机宽度，再切回 1440 px 桌面宽度。检查导航可用、标题不被遮挡、按钮可点击，页面没有横向溢出。

页面视觉和导航验收不代表模型生成链路已经验证；真实模型冒烟需单独记录结果。


## 本轮统一规范与交互

详细规则和参考证据见项目根目录 [design.md](../../../design.md)。全站复用全局语义颜色、字级、间距，以及 `components/ui` 中的 Dialog、Popover、Toast、危险操作确认。侧栏展开240px、收起64px；品牌区可展开，图标导航保留，桌面偏好同时保存到本地和非敏感cookie供首屏恢复。手机使用遮罩抽屉，不继承桌面展开状态。

新增界面自动化使用本机 Chrome 和 Playwright。测试拦截全部API，使用隔离的项目/素材/视频样例，不会调用模型或修改真实数据。

```bash
# 终端一，构建后启动独立生产预览
NEXT_DIST_DIR=.next-verify npm run build
NEXT_DIST_DIR=.next-verify npx next start --hostname 127.0.0.1 -p 3005
```

```bash
# 终端二，运行界面和弹层交互验证
UI_BASE_URL=http://127.0.0.1:3005 npm run test:ui
```

截图默认写到 `docs/evidence/阶段3-设计规范统一/界面/`，可用 `UI_EVIDENCE_DIR` 覆盖目录。`scripts/fixtures/ui-video.mp4` 是1秒纯色测试片段，仅用于检查视频控件，不是模型生成结果。浏览器检查涵盖8个页面、5种宽度、5种工作台工具、6阶段的6种状态，以及弹层焦点、删除失败、模型重试和JSON错误反馈。

本轮生产预览为 [http://127.0.0.1:3005](http://127.0.0.1:3005)。验收步骤与结果见 [本轮证据包](../../../docs/evidence/阶段3-设计规范统一/验收说明.md)。已有全量Lint问题仍需单独清理，界面测试通过不等于全量Lint通过或真实模型链路已验证。

## 页面间距与滚动验收

本轮所有页面共用`.xyq-main`作为唯一页面滚动区，并预留稳定的滚动条空间。页面标题、正文、工作流顶部与底部操作区、工作室输入卡和灵感区使用同一组左右边界：视口宽度≥1024px时40px，768–1023px时24px，<768px时16px；页面容器不再独立限宽或居中。

切换页面、项目会话或工作流阶段后，主滚动区回到顶部；同一页面或阶段的数据刷新保留滚动位置。工作流头尾在主滚动区内sticky，`ResizeObserver`测量真实高度并更新scroll-padding；320px窄屏控件换行后也使用实际高度。Dialog同样由一个滚动区容纳header/body/footer，使用sticky头尾、稳定滚动条空间和动态scroll-padding，避免焦点与首尾内容被遮挡。完整规则见[设计规范第5、6、9节](../../../design.md)。

布局审计由`scripts/layout-audit.mjs`执行，使用已安装的Playwright与本机Chrome。API由隔离样例提供，写请求和外部网络请求会被阻止；无需真实模型Key，也不需要为此启动后端。先保持一个前端预览运行，再在另一终端执行：

```bash
# 默认访问 http://127.0.0.1:3004
npm run test:layout

# 预览运行在3005时显式指定
UI_BASE_URL=http://127.0.0.1:3005 npm run test:layout
```

默认覆盖320、390、768、1024、1512、1920px六种宽度，分别检查侧栏展开/收起（手机为抽屉打开/关闭）。8个普通页面场景与6个工作流阶段的短/长内容组成240个矩阵场景，另有客户端navigation与running状态检查。检查包括左右边界误差≤1px、滚动两端、sticky头尾可见性、弹窗/抽屉开关前后的边界稳定，以及页面/阶段切换后的滚动位置。这些数字描述默认覆盖范围，不代表已经通过；额外场景数、断言数和最终结果以本次运行报告为准。

默认JSON报告写到`/tmp/DramaCoo-layout-audit/results.json`。可通过`LAYOUT_REPORT`指定报告文件，通过`LAYOUT_SCREENSHOTS_DIR`保存代表截图；目录不存在时脚本会创建。以下命令将本轮报告与截图放到项目证据目录：

```bash
UI_BASE_URL=http://127.0.0.1:3005 \
LAYOUT_REPORT=../../../docs/evidence/阶段3-布局对齐/layout-results.json \
LAYOUT_SCREENSHOTS_DIR=../../../docs/evidence/阶段3-布局对齐/界面 \
npm run test:layout
```

局部复查可设置`LAYOUT_WIDTHS=320,1512`、`LAYOUT_ROUTES=home,character_design`、`LAYOUT_LENGTHS=short,long`或`LAYOUT_SIDEBARS=open,closed`；筛选后的运行不能替代全量验收。默认截图只保存代表场景，完整几何覆盖以JSON报告为准。

本轮验收说明与实际结果存放在[布局对齐证据包](../../../docs/evidence/阶段3-布局对齐/验收说明.md)。截图没有溢出不足以证明页面对齐，应同时核对几何报告；布局审计也不替代真实模型冒烟、生产构建或已有业务测试。
